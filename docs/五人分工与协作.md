# 五人分工与协作建议

以下按模块划分责任，尚未指定具体成员。每人负责自己的实现、验证、说明和Git记录，最终由其他成员交叉复现。

| 角色 | 主要职责 | 可检查产出 |
| --- | --- | --- |
| 1 数据负责人 | 处理重复和标签冲突，固定划分，统一类别映射，实现数据加载与增强 | 划分CSV、数据加载代码、数据校验报告 |
| 2 模型负责人 | 实现ResNet18分类网络与CORAL损失，检查梯度、数值和BatchNorm策略 | 模型与损失代码、数学性质及梯度检查、方法说明 |
| 3 训练评估负责人 | 管理服务器虚拟环境，实现训练和评估，完成三个方向的三组对照及消融 | 运行入口、固定配置、日志、检查点、`results.csv` |
| 4 前端工程负责人 | 实现模型加载和预测接口，支持单图、批量、示例图、特征投影及耗时展示 | 可运行Demo、预测接口、运行说明 |
| 5 分析与文档负责人 | 制作曲线、混淆矩阵和t-SNE，分析失败与负迁移，统筹报告和答辩PPT | 分析图、错误案例、分析报告、技术文档整合、答辩PPT |

建议由训练评估负责人兼任项目统筹，维护实验排期和结果版本。分析与文档负责人负责整合，各成员提供自己模块的方法、实现、验证和限制，避免文档任务集中在一人身上。

协作顺序：

1. 数据负责人先冻结类别、划分和重复处理规则；其他模块统一使用同一清单。
2. 模型与训练负责人共同跑通首个方向的Source-only、Deep CORAL、Target-supervised，再扩展三个方向；前端可用同一预测接口并行推进。
3. 分析负责人提前约定日志和结果字段；测试集仅用于最终评价，无监督适配不使用目标域标签。
4. 每人使用自己的Git身份提交。正式结果、配置和报告对应同一版本，由其他成员在服务器上交叉复现。
